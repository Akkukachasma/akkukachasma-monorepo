# Monorepo

- Consolidates split standalone repos into one **pnpm-workspace + Turborepo monorepo** under `apps/`; the separate local folders (e.g. `akkukachasma_be`, `akkukachasma_fe-main`) are treated as throwaway *sources* to be merged in, with the monorepo as where all work happens. Merges app-by-app (backend landed first, then "ab frontend daal do") and expects the later app to follow the same pattern as the one already merged. Confidence: 0.7
- When importing a standalone app into `apps/<app>`, strip the source repo's own tooling during the move: exclude `node_modules`, `.next`, `.git`, `.github`, `.husky` and lockfiles; drop the app-level `"prepare": "husky"` script and the app-level `packageManager` field (the workspace root owns the package manager version); rename the package to the workspace scope convention (`@akkukachasma/web` to match `@akkukachasma/api`) so filters read uniformly (`pnpm --filter @akkukachasma/web dev`). Confidence: 0.55
- For a Next.js app inside the monorepo, set `outputFileTracingRoot` to the workspace root in `next.config.js` so Next traces from the repo (not `$HOME`) and the workspace-root warning goes away. Confidence: 0.6
- pnpm's strict linking in the workspace surfaces undeclared dependencies that were invisible when the app ran standalone (e.g. `axios` imported by `delhivery.service.ts` but never listed in `apps/api/package.json`). Fix by declaring the dep in the owning app and re-running a root install — never by shimming module paths or relying on hoisting. Confidence: 0.6
- The monorepo tree is **not** the source of truth once it drifts from what's deployed: when the live site's rendered output doesn't match what the monorepo code should produce, the user states the real code lives in `/Users/apple/akkukachasma.com` (the standalone backend/ + frontend/ folder) and the monorepo was seeded from the wrong copy. Diff and build against that folder, not the monorepo, and say so explicitly instead of continuing to patch `apps/web`/`apps/api`. Confidence: 0.65
- Wants the monorepo moved to the **current** pnpm major's config keys, not legacy ones (e.g. `allowBuilds` replacing `onlyBuiltDependencies`), and pnpm's auto-inserted `"set this to true or false"` placeholders are treated as a real blocker to fill in with deliberate per-package true/false decisions, not to leave or delete. Confidence: 0.5
- Exposes the whole monorepo to one command: expects the root `pnpm dev` to run all apps together (web, docs, api) *and* the per-app `pnpm --filter <pkg> dev` form to be handed over for running in their own terminal. Confidence: 0.6
- The monorepo is meant to be a faithful mirror of the real repo's backend and frontend ("ye monorepo mein hona issi ka backend aur frontend"), and when its copy looks stale he gives standing permission to work from the standalone folder instead — "agar tumhe lagta hai monorepo mein code bilkul purana hai, you can use this code". Treat the monorepo and the real repo as two checkouts of the same upstream, and settle which is current with a `diff -rq`/md5 parity check plus remote-branch dates rather than by assumption. Confidence: 0.6
- His local shell has `NODE_ENV=production` exported globally, which silently poisons a plain `pnpm dev` (Next warns, API resolves to the production URL). When handing over local-run commands, prefix them (`NODE_ENV=development pnpm --filter @akkukachasma/web dev`) and call the leak out, otherwise the commands you give him fail for a reason that isn't in the code. Confidence: 0.5
- Repo is branch-per-environment (`main` / `qa` / `prod`, remote `arpansource/akkukachasma.com`). When seeding `apps/{api,web}` from the standalone folder, seed from the branch that matches the **target environment** (e.g. `origin/qa` for the QA host) — local default-branch HEAD is routinely months behind and is what produced the wrong content in the first place. Confidence: 0.5
- Once a branch swap has been reasoned out and approved, he sequences the wipe as an explicit order rather than a merge: (1) back up `.env` + a full `rsync -a --exclude node_modules --exclude .next --exclude dist --exclude .git --exclude coverage` snapshot of `apps/web`/`apps/api` into the scratchpad, (2) `rm -rf apps/web apps/api`, (3) `rsync` the extracted branch code back into those two paths (excluding `.git`, `node_modules`, build output), (4) re-adapt to workspace conventions — rename packages to `@akkukachasma/web` / `@akkukachasma/api` and **delete the imported `pnpm-lock.yaml` / `pnpm-workspace.yaml` / `bun.lock`** so only the root lockfile resolves, (5) `pnpm install` from the workspace root, (6) `prisma generate`, (7) boot both apps and verify locally. He wants the old code *gone*, not merged or left to coexist alongside. Confidence: 0.6
- Verifies recoverability before the destructive step instead of trusting it: check `git status --short apps/` to see whether the app dirs are even tracked (untracked = not recoverable from git), and enumerate every recovery source on disk (`akkukachasma.com`, `akkukachasma_fe-main`, `akkukachasma_be`) plus the already-extracted branch dir, printing OK/MISSING per path. Only wipe once each one is confirmed present. Confidence: 0.6
- The `.env` you back up before a wipe is not automatically valid for the code you import afterwards — read the restored file and check it still covers what the new branch code reads, because a var can have been stripped from the saved copy while the imported code hard-requires it (a `# qa database url` comment with no `DATABASE_URL=` under it). Re-add the missing var in place under its comment rather than pasting a whole new file, and write a fresh minimal `.env` for an app that had none (frontend: `NEXT_PUBLIC_API_URL=http://localhost:8001`, `NEXT_PUBLIC_SITE_URL=http://localhost:3000`, matching the backend's dev port). Confidence: 0.55
- A destructive content swap must be staged, not checked out: bank the working copy's uncommitted work first (`git diff -- <changed files> > <scratchpad>/local-fixes.patch`, with a one-line "these are type-safety fixes, worth keeping" judgment about whether to reapply it), copy the workspace-only files that live outside git (`.env`, `next.config.*`) into a `preserve/` dir in the scratchpad, then extract the target branch without touching the repo (`git archive origin/qa frontend backend | tar -x -C <scratchpad>/qa`) and `diff -rq` it against `apps/web`/`apps/api` before wiping anything. This keeps the replace reversible and no local fix silently dropped. When a `preserve` copy silently finds nothing, run `git check-ignore -v <path>` to separate "never committed" from "deleted" instead of reporting the file missing. Confidence: 0.5
